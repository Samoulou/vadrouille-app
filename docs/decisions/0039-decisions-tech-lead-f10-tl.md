## F10-TL-4 — Service worker et page de repli
**Retenu, avec les écarts de F10b entérinés** (revue consolidée de #212). Les points suivants remplacent ceux de la proposition qu'ils citent :

1. **Aucune écriture à la demande sous `/_next/static/`** (remplace la fin du point « aiguillage » 2). Le cache « interface » est rempli à l'installation seulement : coquille `/hors-ligne`, scripts et feuilles de style qu'elle référence, polices trouvées dans ces feuilles (`next/font` les sert sous `/_next/static/media/`). Une requête `GET` de la même origine sous `/_next/static/` est servie depuis ce cache si elle y est, sinon par le réseau, **sans écriture**. Motif : C25 exige que la liste des entrées reste identique après des visites en ligne, et une écriture à la demande ferait grossir le cache à chaque build visité. La règle « statut 200, type `basic`, non redirigée » reste exigée à l'installation.
2. **Nom du cache par empreinte** (remplace « nommé avec l'identifiant de build ») : `vadrouille-interface-<empreinte>`, l'empreinte étant calculée sur la liste des ressources de la coquille, dont les noms changent à chaque build. À l'activation, tout cache `vadrouille-interface-*` autre que le courant est supprimé.
3. **Requêtes laissées au réseau** (précise le point « aiguillage » 3) : paramètre `_rsc` ; en-têtes `RSC`, `Next-Router-Prefetch`, `Next-Router-State-Tree`, `Next-Action` ; méthode autre que `GET` ; chemin sous `/api/` ; toute autre origine (Google compris). Aucun `respondWith` pour elles.
4. **Aiguillage dans `public/sw-route.js`, script classique** chargé par `importScripts("/sw-route.js")`, et non `public/sw-route.mjs`. Motif, de prudence : le dépôt ne fixe pas de matrice de navigateurs ciblés, et un service worker classique est la forme la plus largement prise en charge, alors que le type module (`register(…, { type: "module" })`) est arrivé plus tard dans certains navigateurs ; le choix classique n'exclut aucun navigateur et ne coûte rien ; le test unitaire exécute le script dans un contexte `vm` isolé. `/sw-route.js` reçoit le même `Cache-Control: no-cache` que `/sw.js` (F10-TL-8) et le même bloc ESLint (F10-TL-5), **sauf** `caches.open`, réservé à `public/sw.js` seul.
5. **Q306 (Q-F10b-2) — aucun identifiant de build exposé au MVP.** Pas de `?build=` à l'enregistrement, pas de variable d'environnement publique. Limite acceptée : un nouveau build n'atteint un appareil déjà installé que lorsque `public/sw.js` ou `public/sw-route.js` change (le navigateur ne réinstalle pas un script identique) ; la coquille gardée reste cohérente avec ses propres scripts, elle est seulement plus ancienne, et ne contient aucune donnée. À rouvrir avec la copie hors ligne (« Après le MVP »), ou si une correction de la page de repli doit atteindre les appareils sans changement du service worker.
6. Inchangé : service worker écrit à la main, sans dépendance ; enregistré seulement par le module désigné (`src/lib/offline/register.ts`), à l'ouverture de `R15` avec le réseau, à toute date ; navigation de l'origine (`/p/` compris) : réseau sans écriture, réponse rendue telle quelle (404 et 500 compris), redirection vers `/hors-ligne` seulement si le `fetch` échoue ; navigation vers `/hors-ligne` : réseau, puis coquille du cache, jamais redirigée ; ni heure, ni IndexedDB, ni Web Storage, ni cookie.

1. `use.serviceWorkers: "block"` au niveau global de `playwright.config.ts`, vérifié par un test unitaire ; pas de projet supplémentaire. `test.use({ serviceWorkers: "allow" })` seulement dans les fichiers ou blocs qui ont besoin du service worker (aujourd'hui : `hors-ligne.e2e.spec.ts`, le bloc « page de repli » de `voyage.a11y.spec.ts` et de `voyage.visual.spec.ts`, le contrôle de persistance de `carte.e2e.spec.ts` ; F10c ajoute le bloc de C36), liste vérifiée par le même test unitaire.

B2 modifie aussi `TripShell`. `SharedShell` ne monte que ce que la vue montre, ce qui sert aussi le budget de F10-TL-10.

**Précision — sans duplication** : `SharedShell` compose les primitives existantes (`DayMap`, `Sheet` et `sheet-model`, `DayTabs`, `useLargeScreen`, `useElementSize`). Si une logique de `TripShell` est nécessaire telle quelle (par exemple le calcul de la marge de la carte d'après la taille du panneau), F10c l'extrait dans un module commun importé par les deux, au lieu de la recopier. Le reste de la proposition est retenu : points de type `stop` seulement, clé locale `key`, tracé sans terminus, marqueurs non interactifs, état de remplacement sans positions, carte simulée injectée par `CarteProvider` dans les tests seulement.
